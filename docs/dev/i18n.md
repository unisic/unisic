# Internationalization (REQUIREMENT)

Every user-facing string MUST be wrapped in `qsTr()` (QML) / `tr()` (C++) **and** translated in all seven `i18n/unisic_{en,pl,es,it,fr,ru,de}.ts` files. English is the source language - its `.ts` mirrors the source text (translation == source). Workflow for any new/changed string: (1) add the `qsTr`/`tr` call; (2) run `cmake --build build --target update_translations` - lupdate rescans C++ + `qml/*.qml` and appends the new strings as `type="unfinished"` with an empty `<translation>`; (3) fill every unfinished `<translation>` in **all seven** files and drop the `unfinished` marker. A plain `cmake --build build` runs lrelease and bakes the `.qm` into the qrc (`HAVE_TRANSLATIONS`), so any `unfinished`/empty entry silently falls back to English at runtime - do not ship those. Keep placeholders (`%1`), filename tokens (`%date%`), file globs (`*.png`), and program names (`pw-play`/`paplay`/`aplay`) verbatim; match the per-language sound-cue convention already in the files (Shutter → Migawka / Obturador / Otturatore, Beep → Bip / Pitido / Bip, Off → Wyłącz / Desactivado / Spento, …). New QML component files must be added to `qt_add_qml_module` in `CMakeLists.txt` so lupdate scans them.
