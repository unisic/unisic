# Unisic - Release notes

Per-version notes shown in-app when the version label is clicked. The section
whose `##` heading matches the running version (see `UNISIC_VERSION`) is shown;
within it, the `### English` / `### Polski` block for the toggled language is
displayed. Keep the newest version at the top; each version is translated as a
whole per release (not per individual change).

## 0.8.3

### English
**Added**
- **A screenshot can be a GIF now**: GIF joins PNG, JPEG and WebP in Settings > Image > Format, so every capture you take is saved as one, copied to programs that want a file as one, and uploaded as one. When you only want a single picture that way, the editor's **More** menu and every picture tile in History have **Save as GIF**, which writes a second file beside the one you already have and leaves the original alone. The quality slider works here too, in the only way a GIF can answer it: it buys colours, from 64 at the low end to the full 256 at the top, and a lower setting really does make a smaller file. Transparency survives. This needs ffmpeg, the same program the recorder already needs, because Qt itself cannot write a GIF at all - without it the two menu entries are greyed out with the reason, and a capture that would have been saved as GIF is saved as PNG with a note saying so, rather than a file that lies about what is inside it.
- **Pictures can change format on their own, in the four places it is worth doing**: a new **Image conversion** group in Settings > Image collects all of it. **Convert files I bring in** takes a picture you dropped, pasted or opened here and saves it in your chosen format instead of the one it arrived in, as a new file beside the original, which is never touched. **Convert files over a size** watches what a capture weighs after it is saved and, past the megabyte limit you set, re-encodes it into the format you picked - and if the new file does not actually come out smaller, it keeps the original and says nothing, so the rule can never make a file worse. **Upload format** lets the picture you send be a different format than the one on your disk, in either direction: lossless PNG kept locally, something lighter sent out, or the reverse. And every picture tile in History now offers **Convert to PNG / JPEG / WebP / GIF**, each writing a second file beside the one you have. Every conversion uses the quality slider above, transparency is respected everywhere - a picture with any goes to PNG rather than to a JPEG that would have turned it black, and says so - and anything you picked by hand is never overridden by the size rule.
- **A watermark that covers the whole picture, not just one corner**: the watermark could only ever be one stamp in one of six spots, which anyone can crop off in five seconds. Settings > Image > Watermark has a new **Pattern** with five ready-made layouts. **One stamp** is what you had, and is still the only one that uses **Position**. **Tiled** and **Diagonal tiled** repeat a small stamp across the entire capture, offset every other row and, in the diagonal case, running corner to corner, so there is no rectangle left to crop that does not contain the mark. **Four corners** puts one in each corner. **Diagonal band** is a single large mark running across the middle, the way a draft document is stamped. Every layout works with both a text watermark and your own logo, the opacity slider applies to the whole mark as before, and the picture's size never changes. Next to it is a **Size** drop-down with ready sizes from 25% to 400% and a field at the bottom for any number of your own between 10% and 400%: 100% is the size the pattern picks for itself, which is a fraction of the capture's shorter side, so one setting looks the same on a small window and on a 4K screen. And the whole group now has a **live preview** above it - a sample capture stamped by the same code your screenshots go through, redrawn as you move anything, with a light half and a dark half in it, because a mark that reads perfectly over one can vanish over the other.
- **Servers that want the file name in the address, buzzheavier.com among them**: a curl server could only ever be a folder to drop a file into. The name was glued onto the end of the address, the server's answer was thrown away, and headers could not be sent at all, so a host that wants the name inside its own address and replies with the link was simply out of reach. Write **%file%** anywhere in the request URL and the name lands there instead, headers work the way they do for the other server kind, and the URL extractor now reads the reply of a curl server too - so the link the server hands back is the link you get, and a file server that answers nothing keeps working off the public URL base exactly as before. buzzheavier.com is ready-made in the server list: no account, no key, pick it and upload.
- **Recording quality now reads as a percent, and every sound source can keep its own track**: the video quality setting was a raw CRF number where lower meant better, which is the wrong way round for anyone who has not read an encoder manual. It is a **Video quality** percentage now, in Settings > Recording and on the Record page: 50% is exactly what the old default encoded at, so nothing you recorded before changes, 100% is mathematically lossless and very large, and below 25% small text starts to smear. Ready values from 25% to 100% sit in the list and any number of your own goes in the field at the bottom. Next to it, **Separate audio tracks** stops system audio and the microphone from being mixed into one inseparable track: with it on, each source is written as its own named track - "System audio", "Microphone", "Application audio" - so an editor can duck one against the other, and the names survive a paused recording, the final MP4 or WebM conversion and a trim done here. It needs at least two sources, since with one there is nothing to separate. And because most players only ever play a file's first track, that first track is a ready-made mix of everything - the file sounds complete wherever you play it, and the separate source tracks sit behind it for the editor.

- **The microphone can record from any input you choose**: recording always took the system's default input, and there was no way to point it anywhere else without changing the default for the whole desktop. Settings > Recording > Audio has a **Microphone input** list now: Default input keeps following the system setting, or pick a concrete device - a second microphone, or a virtual source such as an EasyEffects-processed one - and the microphone track records from exactly that, no matter what the rest of the desktop uses. Refresh re-reads the list after plugging something in. Needs the pw-dump helper, which comes with PipeWire's own utilities.
- **The trim window edits sound, not just time**: the recording's audio tracks are listed under the timeline, by the names they carry - "System audio", "Microphone" - each with a switch and a volume slider. Turn a track off and the saved copy does not contain it; set 60% and it comes out at 60%. On a recording that leads with the ready-made mix, that mix is rebuilt from your edited tracks, so muting the microphone really silences what players play, instead of only removing a track nobody listens to. The preview plays your edits live: flip a switch or drag a slider and what you hear is the cut you are about to save (with one honest limit - a volume above 100% previews at full volume and applies fully only to the saved file). Leave everything at 100% and the audio passes through untouched, byte for byte in a lossless cut. None of this ever re-encodes the video, so a lossless cut stays instant even while the sound is being reshaped. And a cut of a multi-track recording keeps ALL of its tracks now - the fast lossless mode used to silently keep only the first one.

**Improved**
- **Capture actions stay visible, and custom themes control every interface colour**: selection, star and action controls on History tiles no longer wait for a mouse hover, and the image-first notification keeps its actions visible for touch and assistive technology too. Screenshot scrims, modal backdrops, recording-frame contrast and release-note category colours now all come from optional theme tokens instead of component literals. Existing JSON themes remain valid and receive safe defaults; a theme can override the new tokens when it wants exact control. The recording badge's pause, resume and stop controls also expose names and press actions to screen readers without stealing keyboard focus from the application being recorded.
- **The variables a server field understands are buttons now, and they look like variables**: writing **%file%**, **$base64$** or **$json:data.link$** correctly meant knowing they existed at all, and the only hint was a grey example that vanished the moment you typed anything. Click into the request URL, the JSON body, the URL extractor or the filename template in Settings and a row of chips floats over the form just under that field, one per variable it really understands, each naming what it puts there; the row floats rather than sitting in the layout, so nothing below it moves, and it goes away when you leave the field. Click a chip and it is typed in at the cursor; for the two that need something from you, **$json:$** and **$regex:$**, the cursor lands inside the token, where the path goes - and a second chip clicked straight after lands after that token rather than inside it, so two clicks give you two variables and not one nested in the other. A variable already in the text is drawn as a pill, so it reads as one thing to click past instead of six characters of punctuation, and a half-written one stays plain text until it is complete, which is exactly the moment it starts to work. The http request URL learned **%file%** along the way: put the token anywhere in the address and the file name lands exactly there, which is what an API that wants the name in the path needs, and leaving it out sends the address exactly as typed - only the FTP/SFTP kind still appends the name for you, because that is what a folder means. Fields that substitute nothing, such as the extra form fields, show no chips at all: the list comes from the code that performs the substitutions, so it cannot offer you a variable that would have been sent literally. The filename template gets the same treatment, with its six tokens (**%date%**, **%time%**, **%datetime%**, **%unix%**, **%rand%**, **%i%**) one click away instead of spelled out in a caption you had to copy by hand.
- **Hotkey setup no longer pauses the window**: registering, checking, repairing and changing Plasma shortcuts now waits for KGlobalAccel asynchronously. The same daemon-authoritative conflict checks and the same safe shortcut flags remain in force, but a slow D-Bus reply can no longer block the visible interface. Background encoder, audio-device, preview, clipboard and portal-image work now returns through owned Qt future watchers as well, removing a cross-thread lifetime risk during shutdown.

- **The capture overlay says which capture it is**: every mode froze the screen and drew the same grey chrome, so a screenshot, a measurement, a text read and the two recordings were indistinguishable until the shot was already taken - or the recording had already started. The overlay names itself at the top of the screen now, with the screen edge and the selection handles in that mode's colour, and unlike the hint line it stays there for the whole session rather than disappearing the moment you start dragging. The colour only backs up the word, because a colour alone says nothing on a greyscale screen. The confirm button and the hint tell the truth as well: it reads Record GIF, Record video or Read text where it used to say Start or Capture for all five, and screen readers get the mode in the overlay's spoken name. The badge and the frame can be turned off in Settings > Capture overlay > Show which capture mode is running, and a custom theme can set the five colours (modeShot, modeMeasure, modeOcr, modeGif, modeVideo); the honest button and hint wording stays either way.
- **You can see the capture overlay without taking a capture**: the overlay only exists while a capture is running, over whatever is on your screen and holding the keyboard to itself, so every option that shapes it was a guess - the toolbar position and the new mode badge went unnoticed entirely. Settings > Appearance > Capture overlay opens with a live picture of it now: the mode badge, the coloured frame, the selection with its handles and size readout, the alignment guides, the pixel loupe and the toolbar in the position you picked, all redrawn as you change them. A mode list under it switches the picture between screenshot, measurement, text read, GIF and video, so you can see what a mis-fired hotkey would have looked like before it fires. It is a mock screen, not a capture: nothing is recorded, and the list changes only the picture. The mode indicator itself now has two styles: the named badge at the top of the screen as before, or the mode's icon drawn large and faded in the middle, which names the mode without a strip of chrome over the desktop and has your selection cut out of it, so nothing is drawn over the region you are framing while the rest of the mark keeps naming the capture.
**Fixed**
- **Windows can be resized by their edges again**: with Unisic's own window decoration (the default), the main window, the editor and the trim window had no live edges - the pointer never turned into a resize arrow and dragging the border did nothing, because a window that draws its own title bar gets no resize border from the system and has to provide one itself. All three now answer on every edge and corner exactly like a system-decorated window: the cursor changes, the drag resizes, and the compositor drives the resize itself so it behaves natively. A maximized window keeps its edges quiet, as it should.
- **Switches you could not switch**: a switch clicked right after a wheel scroll often did nothing. Each notch of the wheel glides the view into place over a tenth of a second, and a click that landed during that glide had its switch slide out from under the pointer between pressing and letting go, which counts as a click on nothing. Pressing anywhere now stops the glide on the spot, so whatever is under the pointer stays there, and the switch itself answers to a few pixels around its edge as well.
- **The wheel scrolls where it used to crawl**: the system check, the update prompt, the release notes, the confirmation and shortcut sheets, the colour picker, and both the pane list and the search results in Settings each scrolled by a few pixels per notch, or ignored the wheel entirely and left the middle-button drag as the only way through. They all take the same wheel step as the rest of the app now, a long spin still covers ground faster, and middle-button dragging works in all of them too.
- **An uploaded capture is one tile in History, not two**: uploading from the editor put a second tile next to the one already holding the capture, so the same picture sat in History twice - once as the file on your disk, once as the link on the server, each missing what the other had. The upload now attaches its link to the tile the capture already owns, so one tile carries both. Saving from the editor works the same way: a capture you had not saved yet fills in its own tile instead of starting a new one, and its thumbnail is redrawn from what you actually edited. Uploads started from the notification card or from a tile in History already behaved this way.
- **A .jpeg file is no longer re-encoded on its way out**: with the upload format set to JPEG, a file already named .jpeg counted as being in some other format and was encoded again before it was sent, which costs quality and gains nothing - .jpg and .jpeg are the same file under two spellings. Only a file that really is in another format is converted now, and the same rule is used everywhere else a picture might be converted, so the four places that ask it can no longer disagree.
- **Drawing no longer erases what you already drew**: while you dragged a new shape across the editor, freehand strokes and highlighter marks already on the picture were cut away wherever the shape passed over them, and only came back when something forced the whole picture to be redrawn. Only the part of the picture that changes is repainted, for speed, and the area a finished stroke occupies was measured wrongly: it came out as a small square around the stroke's last point instead of the whole stroke, so anywhere else the stroke was treated as empty and wiped. The area is measured across every point of the stroke now, so a drawing stays whole no matter what you draw over it.
- **The installer now gets you the newest version instead of explaining why you cannot have it**: after installing it said "the newest Unisic is 0.8.2, but the package built for your system is 0.8.1 so far" and stopped there. Worse, that second number was read from what already sat on your computer rather than from the software source it came from, and the two match only by accident: a copy the install had not replaced was reported as the source being behind when it was not. The source itself is asked now - Fedora's COPR, the apt source for Debian and Ubuntu, openSUSE's, Flathub for the Flatpak, the releases page for the portable version - and when it really is a version behind, which lasts up to a day after a release while it rebuilds, the installer fetches that version from the releases page and installs it, so you end the run on the newest either way. Your software source stays the update channel and takes over again as soon as it catches up. On Ubuntu that download is skipped on purpose: the only build that fits Ubuntu is the one in the software source, and a Debian package pushed onto it would simply be refused. What is left is one of three plain answers, whichever is true: you have the newest, or the newest could not be fetched for your system and here is when it arrives, or your system has it waiting in its pending updates. The check also runs for every way of installing now, where before only apt and dnf ever said anything at all.

### Polski
**Dodane**
- **Zrzut ekranu może być teraz GIF-em**: GIF dołącza do PNG, JPEG i WebP w Ustawienia > Obraz > Format, więc każde przechwycenie zapisuje się jako GIF, kopiuje do programów oczekujących pliku jako GIF i wysyła jako GIF. Gdy chcesz tak potraktować tylko jeden obraz, menu **Więcej** w edytorze i każdy kafelek obrazu w Historii mają **Zapisz jako GIF**: powstaje drugi plik obok tego, który już masz, a oryginał zostaje nietknięty. Suwak jakości działa i tutaj, w jedyny sposób, w jaki GIF potrafi na niego odpowiedzieć: kupuje kolory, od 64 na dole skali do pełnych 256 na górze, i niższe ustawienie naprawdę daje mniejszy plik. Przezroczystość zostaje zachowana. Potrzebny jest do tego ffmpeg, ten sam program, którego wymaga już nagrywanie, bo samo Qt nie potrafi zapisać GIF-a w ogóle - bez niego oba wpisy w menu są wyszarzone wraz z powodem, a przechwycenie, które miało trafić do GIF-a, zapisuje się jako PNG z komunikatem o tym, zamiast pliku, który kłamie o swojej zawartości.
- **Obrazy potrafią same zmieniać format, w czterech miejscach, w których warto**: nowa grupa **Konwersja obrazu** w Ustawienia > Obraz zbiera to wszystko. **Konwertuj wczytywane pliki** bierze obraz przeciągnięty, wklejony albo otwarty tutaj i zapisuje go w wybranym przez Ciebie formacie zamiast w tym, w którym przyszedł, jako nowy plik obok oryginału, którego nic nie rusza. **Konwertuj pliki powyżej rozmiaru** patrzy, ile waży zapisane przechwycenie, i powyżej ustawionego przez Ciebie limitu w megabajtach koduje je do wybranego formatu - a jeśli nowy plik nie wychodzi mniejszy, zostawia oryginał i nic nie mówi, więc reguła nigdy nie pogorszy pliku. **Format wysyłki** pozwala wysyłanemu obrazowi być w innym formacie niż ten na dysku, w obie strony: bezstratny PNG trzymany lokalnie, coś lżejszego wysyłane na zewnątrz, albo odwrotnie. A każdy kafelek obrazu w Historii ma teraz **Konwertuj do PNG / JPEG / WebP / GIF**, gdzie każda pozycja tworzy drugi plik obok tego, który masz. Każda konwersja korzysta z suwaka jakości powyżej, przezroczystość jest wszędzie szanowana - obraz, który ją ma, trafia do PNG zamiast do JPEG-a, który zrobiłby z niej czerń, i mówi o tym - a niczego wybranego ręcznie reguła rozmiaru nie nadpisuje.
- **Znak wodny pokrywający cały obraz, a nie jeden róg**: znak wodny mógł być tylko jednym stemplem w jednym z sześciu miejsc, co każdy odetnie w pięć sekund. Ustawienia > Obraz > Znak wodny mają nowy **Wzór** z pięcioma gotowymi układami. **Jeden znak** to dotychczasowe zachowanie i jedyny układ, który korzysta z **Pozycji**. **Kafelki** i **Ukośne kafelki** powtarzają mały znak na całym przechwyceniu, z przesunięciem co drugi rząd, a w wersji ukośnej biegną od rogu do rogu, więc nie zostaje prostokąt do wycięcia, w którym znaku by nie było. **Cztery rogi** umieszczają po jednym w każdym rogu. **Ukośny pas** to jeden duży znak przez środek, tak jak stempluje się dokument roboczy. Każdy układ działa zarówno ze znakiem tekstowym, jak i z własnym logo, suwak przezroczystości dalej dotyczy całego znaku, a rozmiar obrazu nigdy się nie zmienia. Obok jest lista **Rozmiar** z gotowymi wielkościami od 25% do 400% i polem na dole na dowolną własną liczbę od 10% do 400%: 100% to rozmiar, który wzór dobiera sam, będący ułamkiem krótszego boku przechwycenia, więc jedno ustawienie wygląda tak samo w małym oknie i na ekranie 4K. A nad całą grupą jest **podgląd na żywo** - przykładowe przechwycenie ostemplowane tym samym kodem, przez który przechodzą Twoje zrzuty, przerysowywane przy każdej zmianie, z jasną i ciemną połową, bo znak czytelny na jednej potrafi zniknąć na drugiej.
- **Serwery, które chcą nazwy pliku w adresie, w tym buzzheavier.com**: serwer curl mógł być tylko katalogiem do wrzucenia pliku. Nazwa doklejała się na końcu adresu, odpowiedź serwera lądowała w koszu, a nagłówków nie dało się wysłać w ogóle, więc host, który chce nazwy w środku własnego adresu i odpowiada odnośnikiem, był poza zasięgiem. Wpisz **%file%** w dowolnym miejscu adresu, a nazwa trafi właśnie tam, nagłówki działają tak samo jak przy drugim rodzaju serwera, a ekstraktor adresu czyta teraz też odpowiedź serwera curl - więc odnośnik, który serwer oddaje, jest tym, który dostajesz, a serwer plików, który nic nie odpowiada, dalej działa na bazowym adresie publicznym dokładnie jak wcześniej. buzzheavier.com jest gotowy na liście serwerów: bez konta, bez klucza, wybierz i wyślij.
- **Jakość nagrania podana w procentach, a każde źródło dźwięku na własnej ścieżce**: ustawienie jakości wideo było surową liczbą CRF, w której mniej znaczyło lepiej, czyli odwrotnie niż spodziewa się każdy, kto nie czytał instrukcji kodera. Teraz jest to **Jakość wideo** w procentach, w Ustawienia > Nagrywanie i na stronie Nagrywanie: 50% to dokładnie to, czym kodowało dotychczasowe ustawienie domyślne, więc nic z wcześniejszych nagrań się nie zmienia, 100% jest matematycznie bezstratne i bardzo duże, a poniżej 25% drobny tekst zaczyna się rozmazywać. Gotowe wartości od 25% do 100% są na liście, a dowolną własną liczbę wpisujesz w polu na dole. Obok **Osobne ścieżki dźwięku** przestają zlewać dźwięk systemowy i mikrofon w jedną nierozdzielną ścieżkę: przy włączonej opcji każde źródło trafia na własną, nazwaną ścieżkę - „Dźwięk systemowy", „Mikrofon", „Dźwięk aplikacji" - więc w montażu można jedno ściszyć względem drugiego, a nazwy przeżywają wstrzymane nagranie, końcową konwersję do MP4 lub WebM i przycięcie zrobione tutaj. Potrzebne są co najmniej dwa źródła, bo przy jednym nie ma czego rozdzielać. A że większość odtwarzaczy gra tylko pierwszą ścieżkę pliku, ta pierwsza jest gotowym miksem całości - plik brzmi w pełni, gdziekolwiek go odtworzysz, a osobne ścieżki źródeł leżą za nim dla montażu.

- **Mikrofon nagrywa z dowolnie wybranego wejścia**: nagrywanie zawsze brało systemowe domyślne wejście i nie dało się wskazać innego bez zmiany domyślnego dla całego pulpitu. Ustawienia > Nagrywanie > Dźwięk mają teraz listę **Wejście mikrofonu**: „Domyślne wejście" dalej podąża za ustawieniem systemowym, albo wybierz konkretne urządzenie - drugi mikrofon czy źródło wirtualne, np. mikrofon przetwarzany przez EasyEffects - a ścieżka mikrofonu nagrywa dokładnie z niego, niezależnie od reszty pulpitu. Odśwież wczytuje listę na nowo po podłączeniu czegoś. Wymaga narzędzia pw-dump, dostarczanego z narzędziami samego PipeWire.
- **Okno przycinania edytuje dźwięk, nie tylko czas**: pod osią czasu wypisane są ścieżki dźwięku nagrania, pod nazwami, które noszą - „Dźwięk systemowy", „Mikrofon" - każda z przełącznikiem i suwakiem głośności. Wyłącz ścieżkę, a zapisana kopia jej nie zawiera; ustaw 60%, a wyjdzie na 60%. Przy nagraniu, które zaczyna się gotowym miksem, ten miks jest budowany na nowo z wyedytowanych ścieżek, więc wyciszenie mikrofonu naprawdę ucisza to, co grają odtwarzacze, zamiast tylko usuwać ścieżkę, której nikt nie słucha. Podgląd gra Twoje zmiany na żywo: przestaw przełącznik albo przesuń suwak, a słyszysz dokładnie to cięcie, które zaraz zapiszesz (z jednym uczciwym ograniczeniem - głośność powyżej 100% w podglądzie gra na pełnej głośności, a w pełni działa dopiero w zapisanym pliku). Zostaw wszystko na 100%, a dźwięk przechodzi nietknięty, przy bezstratnym cięciu bajt w bajt. Nic z tego nigdy nie przekodowuje wideo, więc bezstratne cięcie pozostaje natychmiastowe nawet przy zmienianym dźwięku. A przycięcie nagrania wielościeżkowego zachowuje teraz WSZYSTKIE ścieżki - szybki tryb bezstratny po cichu zostawiał dotąd tylko pierwszą.

**Ulepszone**
- **Akcje przechwyceń pozostają widoczne, a własne motywy sterują każdym kolorem interfejsu**: zaznaczanie, gwiazdka i akcje na kafelkach Historii nie czekają już na najechanie myszą, a powiadomienie z obrazem na pierwszym planie trzyma akcje widoczne również dla dotyku i technologii asystujących. Przyciemnienia zrzutów, tła okien modalnych, kontrast ramki nagrywania i kolory kategorii informacji o wydaniu pochodzą teraz z opcjonalnych tokenów motywu zamiast literałów w komponentach. Dotychczasowe motywy JSON pozostają poprawne i dostają bezpieczne wartości domyślne, a autor motywu może nadpisać nowe tokeny. Przyciski wstrzymania, wznowienia i zatrzymania na plakietce nagrywania udostępniają też nazwy i akcje czytnikom ekranu bez odbierania fokusu nagrywanej aplikacji.
- **Zmienne, które rozumie pole serwera, są teraz przyciskami i wyglądają jak zmienne**: żeby poprawnie wpisać **%file%**, **$base64$** czy **$json:data.link$**, trzeba było w ogóle wiedzieć, że istnieją, a jedyną podpowiedzią był szary przykład znikający w chwili, gdy cokolwiek napisałeś. Kliknij w adres żądania, treść JSON, ekstraktor adresu albo szablon nazwy pliku w Ustawieniach, a tuż pod tym polem wypłynie nad formularzem rząd żetonów, po jednym na każdą zmienną, którą to pole naprawdę rozumie, a każdy mówi, co w to miejsce wstawia; rząd unosi się nad układem, zamiast w nim siedzieć, więc nic pod nim się nie przesuwa, a znika, gdy wychodzisz z pola. Kliknięcie żetonu wpisuje zmienną w miejscu kursora, a przy dwóch, które czegoś od Ciebie potrzebują, **$json:$** i **$regex:$**, kursor ląduje w środku tokenu, tam gdzie idzie ścieżka - a drugi żeton kliknięty zaraz potem trafia za ten token, nie do jego środka, więc dwa kliknięcia dają dwie zmienne, a nie jedną zagnieżdżoną w drugiej. Zmienna, która jest już w tekście, rysowana jest jako pigułka, więc czyta się jako jedna rzecz do minięcia, a nie jako sześć znaków interpunkcyjnych, a niedokończona zostaje zwykłym tekstem, dopóki nie jest kompletna, czyli dokładnie do chwili, w której zaczyna działać. Adres żądania http nauczył się przy okazji **%file%**: wstaw token w dowolne miejsce adresu, a nazwa pliku trafi dokładnie tam, czego potrzebuje API chcące nazwę w ścieżce, a bez tokenu adres idzie dokładnie tak, jak wpisany - tylko odmiana FTP/SFTP nadal dopisuje nazwę sama, bo tego znaczy katalog. Pola, które niczego nie podstawiają, jak dodatkowe pola formularza, nie pokazują żetonów wcale: lista pochodzi z kodu wykonującego podstawienia, więc nie może zaproponować Ci zmiennej, która poszłaby dosłownie. Szablon nazwy pliku dostaje to samo: jego sześć tokenów (**%date%**, **%time%**, **%datetime%**, **%unix%**, **%rand%**, **%i%**) jest o jedno kliknięcie stąd, zamiast być wypisanym w podpisie, który trzeba było przepisywać ręcznie.
- **Konfigurowanie skrótów nie zatrzymuje już okna**: rejestrowanie, sprawdzanie, naprawianie i zmienianie skrótów Plazmy czeka teraz na KGlobalAccel asynchronicznie. Nadal działają te same wiążące sprawdzenia konfliktów po stronie demona i te same bezpieczne flagi skrótów, ale wolna odpowiedź D-Bus nie może już zablokować widocznego interfejsu. Zadania kodera, list urządzeń dźwiękowych, podglądu, schowka i obrazu z portalu również wracają teraz przez posiadane obserwatory przyszłych wyników Qt, co usuwa ryzyko czasu życia między wątkami przy zamykaniu.

- **Nakładka przechwytywania mówi, jakie to przechwytywanie**: każdy tryb zamrażał ekran i rysował tę samą szarą otoczkę, więc zrzut, pomiar, odczyt tekstu i oba nagrania były nie do odróżnienia, dopóki zrzut nie był już zrobiony - albo nagranie już nie trwało. Nakładka nazywa się teraz u góry ekranu, krawędź ekranu i uchwyty zaznaczenia mają kolor tego trybu, a w odróżnieniu od linii podpowiedzi zostaje to na całą sesję, zamiast znikać w chwili rozpoczęcia przeciągania. Kolor jedynie wspiera słowo, bo sam kolor nic nie mówi na ekranie w odcieniach szarości. Przycisk potwierdzenia i podpowiedź też mówią prawdę: widnieje na nim Nagraj GIF, Nagraj wideo albo Odczyt tekstu tam, gdzie wcześniej dla wszystkich pięciu trybów pisało Rozpocznij albo Przechwyć, a czytniki ekranu dostają tryb w wypowiadanej nazwie nakładki. Plakietkę i ramkę można wyłączyć w Ustawienia > Nakładka przechwytywania > Pokazuj, który tryb przechwytywania działa, a własny motyw może ustawić pięć kolorów (modeShot, modeMeasure, modeOcr, modeGif, modeVideo); uczciwe napisy na przycisku i w podpowiedzi zostają tak czy inaczej.
- **Nakładkę przechwytywania widać bez robienia przechwycenia**: nakładka istnieje tylko w trakcie przechwytywania, na tym, co akurat masz na ekranie, i trzyma klawiaturę dla siebie, więc każda opcja, która ją kształtuje, była zgadywanką - pozycja paska narzędzi i nowa plakietka trybu umykały całkowicie. Ustawienia > Wygląd > Nakładka przechwytywania zaczynają się teraz jej żywym obrazem: plakietka trybu, kolorowa ramka, zaznaczenie z uchwytami i odczytem rozmiaru, linie prowadzące, lupa pikseli i pasek narzędzi w wybranej przez Ciebie pozycji, przerysowywane przy każdej zmianie. Lista trybów pod spodem przełącza obraz między zrzutem, pomiarem, odczytem tekstu, GIF-em i wideo, więc widzisz, jak wyglądałby pomylony skrót, zanim się odpali. To makieta ekranu, nie przechwycenie: nic nie jest nagrywane, a lista zmienia wyłącznie obraz. Sam wskaźnik trybu ma teraz dwa style: nazwaną plakietkę u góry ekranu jak dotąd albo ikonę trybu narysowaną dużą i przygaszoną na środku, która nazywa tryb bez paska interfejsu na pulpicie i ma wycięte w sobie Twoje zaznaczenie, więc nic nie jest rysowane na kadrowanym obszarze, a reszta znaku dalej nazywa przechwytywanie.
**Naprawione**
- **Okna znów da się zmieniać rozmiarem za krawędzie**: przy własnej dekoracji okien Unisic (domyślnej) okno główne, edytor i okno przycinania nie miały żywych krawędzi - kursor nigdy nie zmieniał się w strzałkę zmiany rozmiaru, a przeciąganie ramki nic nie robiło, bo okno rysujące własny pasek tytułu nie dostaje od systemu ramki do chwytania i musi zapewnić ją samo. Wszystkie trzy odpowiadają teraz na każdej krawędzi i w każdym rogu dokładnie jak okno z systemową dekoracją: kursor się zmienia, przeciąganie zmienia rozmiar, a samą zmianą steruje kompozytor, więc zachowuje się natywnie. Okno zmaksymalizowane trzyma krawędzie wyciszone, jak należy.
- **Przełączniki, których nie dało się przełączyć**: przełącznik kliknięty zaraz po przewinięciu kółkiem często nic nie robił. Każde kliknięcie kółka dosuwa widok na miejsce przez jedną dziesiątą sekundy, a klik trafiony w trakcie tego dosuwania miał przełącznik wyjeżdżający spod kursora między naciśnięciem a puszczeniem, co liczy się jako klik w nic. Naciśnięcie gdziekolwiek zatrzymuje teraz dosuwanie w miejscu, więc to, co jest pod kursorem, tam zostaje, a sam przełącznik odpowiada też na kilka pikseli wokół swojej krawędzi.
- **Kółko przewija tam, gdzie wcześniej pełzło**: sprawdzenie systemu, monit o aktualizację, informacje o wydaniu, okna potwierdzeń i skrótów, wybór koloru oraz lista paneli i wyniki wyszukiwania w Ustawieniach przewijały się o kilka pikseli na kliknięcie kółka albo nie reagowały na kółko wcale, zostawiając przeciąganie środkowym przyciskiem jako jedyną drogę. Wszystkie mają teraz ten sam krok kółka co reszta aplikacji, szybkie kręcenie nadal pokonuje dystans szybciej, a przeciąganie środkowym przyciskiem działa w każdym z nich.
- **Wysłane przechwycenie to jeden kafelek w Historii, a nie dwa**: wysyłka z edytora dokładała drugi kafelek obok tego, który już trzymał to przechwycenie, więc ten sam obraz siedział w Historii dwa razy - raz jako plik na Twoim dysku, raz jako odnośnik na serwerze, i każdemu z nich brakowało tego, co miał drugi. Wysyłka dopina teraz odnośnik do kafelka, który przechwycenie już ma, więc jeden kafelek niesie jedno i drugie. Zapis z edytora działa tak samo: przechwycenie, którego jeszcze nie zapisałeś, uzupełnia własny kafelek zamiast zakładać nowy, a jego miniatura jest rysowana od nowa z tego, co naprawdę wyedytowałeś. Wysyłki uruchamiane z karty powiadomienia albo z kafelka w Historii już wcześniej działały w ten sposób.
- **Plik .jpeg nie jest już przekodowywany przy wysyłce**: przy formacie wysyłki ustawionym na JPEG plik nazwany .jpeg liczył się jako będący w innym formacie i przed wysłaniem kodowany był od nowa, co kosztuje jakość i nic nie daje - .jpg i .jpeg to ten sam plik w dwóch zapisach. Konwertowany jest teraz tylko plik, który naprawdę jest w innym formacie, a ta sama reguła obowiązuje wszędzie indziej, gdzie obraz może być konwertowany, więc cztery miejsca, które o to pytają, nie mogą już odpowiadać różnie.
- **Rysowanie nie wymazuje już tego, co narysowałeś wcześniej**: gdy przeciągałeś nowy kształt po edytorze, odręczne kreski i ślady zakreślacza leżące już na obrazie były wycinane wszędzie tam, gdzie przeszedł nad nimi kształt, i wracały dopiero wtedy, gdy coś wymusiło przerysowanie całego obrazu. Dla szybkości przerysowywana jest tylko ta część obrazu, która się zmienia, a obszar zajmowany przez skończoną kreskę był mierzony błędnie: wychodził jako mały kwadrat wokół jej ostatniego punktu zamiast całej kreski, więc wszędzie indziej kreska była traktowana jak puste miejsce i zamazywana. Obszar jest teraz mierzony po wszystkich punktach kreski, więc rysunek zostaje cały, cokolwiek byś po nim rysował.
- **Instalator daje Ci teraz najnowszą wersję, zamiast tłumaczyć, czemu nie możesz jej mieć**: po instalacji pisał „najnowszy Unisic to 0.8.2, ale paczka zbudowana dla Twojego systemu to na razie 0.8.1" i na tym kończył. Gorzej, tę drugą liczbę odczytywał z tego, co już leżało na Twoim komputerze, a nie ze źródła oprogramowania, z którego to przyszło, a te dwie rzeczy zgadzają się tylko przypadkiem: kopia, której instalacja nie podmieniła, była zgłaszana jako zaległość źródła, choć źródło zaległości nie miało. Teraz pytane jest samo źródło - COPR Fedory, źródło apt dla Debiana i Ubuntu, źródło openSUSE, Flathub dla Flatpaka, strona wydań dla wersji przenośnej - a gdy naprawdę jest o wersję w tyle, co trwa do doby po wydaniu, w czasie której się przebudowuje, instalator pobiera tę wersję ze strony wydań i ją instaluje, więc tak czy inaczej kończysz na najnowszej. Źródło oprogramowania pozostaje kanałem aktualizacji i przejmuje z powrotem, gdy tylko nadrobi. Na Ubuntu to pobranie jest celowo pomijane: jedyne wydanie pasujące do Ubuntu leży w źródle oprogramowania, a paczka Debiana wepchnięta na siłę zostałaby po prostu odrzucona. Zostaje jedna z trzech prostych odpowiedzi, ta która jest prawdziwa: masz najnowszą, albo najnowszej nie dało się pobrać dla Twojego systemu i oto kiedy dotrze, albo Twój system ma ją w zaległych aktualizacjach. Sprawdzenie działa też teraz przy każdym sposobie instalacji, a wcześniej odzywało się wyłącznie przy apt i dnf.

## 0.8.2

### English
**Added**
- **Unisic now speaks Russian and German**: both are in Settings › General › Language next to English, Polish, Spanish, Italian and French, and "System" picks one automatically when that is what your desktop is set to. All 1541 pieces of text are translated, none left in English. Every one of them was measured against the space it has on screen, so nothing is cut off in the middle of a word. Neither translation has been read over by a native speaker yet, so a sentence here and there may sound stiff: if you find one, report it and it will be corrected.

**Fixed**
- **Installing on Ubuntu works again, and everywhere else you now get the package built for your system**: the installer downloaded one `.deb` file and handed it to every Debian-based system. That file is built on Debian 13 and, like every program of its kind, will only sit next to the exact version of Qt it was built with - so on Ubuntu it was refused with a wall of text about `qt6-base-private-abi`, and the installer gave up and offered you the portable version instead. It now adds Unisic's own software source first and installs from there, because that is where the build made for your system lives: Debian 13 and Ubuntu 25.10/26.04 from that source, Fedora from Unisic's COPR, openSUSE as before. Updates then arrive with your system's ordinary updates and there is nothing else to set up. On a system we have no build for yet it says so plainly, tries the Debian 13 package anyway, and puts the portable version in your home folder if that is refused, rather than leaving you with nothing. Picking a specific older version still downloads it from the releases page, since a software source only ever carries the newest.
- **Saved server passwords were readable by other accounts on the same computer**: the file that stores your upload destinations - FTP and SFTP logins, and API keys typed into a custom server - was written with the permissions any ordinary new file gets, so any other user account on that machine could open and read it. Only you can read it now, and a file left behind by an earlier version is tightened the first time this one opens it. Nothing has to be entered again. On a computer only you use, nothing was ever within reach of anyone else.
- **A program run after each capture can no longer hang forever**: Settings › Capture › External action hands every new capture to a program of your choice. If that program never finished - stuck on a network drive, or waiting for an answer in a terminal you cannot see - Unisic waited with it for the rest of the session, and the temporary copy of the capture stayed on disk. Such a program now gets two minutes and is then stopped, with a message saying so, and if two minutes is the wrong measure for what your command actually does, you set the limit yourself in Settings › Capture › External action › "Give up after" - anything from 10 seconds to an hour. At most four run at the same time, so holding the capture key down can no longer pile up an unlimited number of them. The messages were rewritten as well: instead of "program not found: oxipng" you get the name of the missing program and what to do about it.
- **A save name beginning with a dot no longer hides the capture**: the name template in Settings › Saving takes whatever you type, and a name starting with a dot produced a hidden file - saved without complaint, then invisible in every file manager you would go looking in. A leading dot is dropped now, and so are dots and spaces at the end, which stop a file from copying onto a Windows or FAT share.
- **The extra colour themes come back when they have gone missing**: Dracula, Nord, Gruvbox and the two Catppuccin palettes are copied into your themes folder once, so you can edit or delete them like any theme of your own. Unisic wrote down in its settings that it had done that, and nowhere else - so a settings file carried to another computer, restored from a backup or picked up by a beta build arrived saying "already done" with no themes folder beside it, and those five palettes then never appeared there at all. The folder itself is checked now: when the whole folder is missing they are written again, while deleting single themes inside it still keeps them deleted. A palette added in a later version also reaches an installation that already exists, which it never used to.
- **The in-app installer is now checked before it runs**: "Install now" in Settings › Updates downloads a small script and runs it with your password to install the new version. Until now the only check was that the file looked like Unisic's installer. Every release now publishes that script as a part of itself, together with a fingerprint of it, and Unisic compares the two before anything is run. If they differ, nothing runs and you are told why. That catches a download that arrived incomplete and one served from a cache still holding an old copy. Releases made before this change carry no fingerprint to compare against, so they install exactly as they did before.
- **The row of buttons on a history tile no longer vanishes while its own menu is open**: pointing at a capture in History slides a row of buttons across its bottom edge, and the last of them opens a menu with the remaining actions. That menu is drawn on top of the window rather than inside the tile, so moving the pointer onto it counted as leaving the tile: the whole row faded away, together with the very button the menu was hanging from. A tile now stays lit for as long as its menu is open.

### Polski
**Dodane**
- **Unisic mówi teraz po rosyjsku i po niemiecku**: oba języki są w Ustawieniach › Ogólne › Język obok angielskiego, polskiego, hiszpańskiego, włoskiego i francuskiego, a „Systemowy" wybierze jeden z nich sam, gdy tak masz ustawiony pulpit. Przetłumaczone jest wszystkie 1541 tekstów, żaden nie został po angielsku. Każdy z nich został zmierzony względem miejsca, jakie ma na ekranie, więc nic nie urywa się w połowie słowa. Żadnego z tych dwóch tłumaczeń nie przeczytał jeszcze rodzimy użytkownik języka, więc gdzieniegdzie zdanie może brzmieć sztywno: jeśli takie znajdziesz, zgłoś je, a zostanie poprawione.

**Naprawione**
- **Instalacja na Ubuntu znów działa, a wszędzie indziej dostajesz paczkę zbudowaną pod Twój system**: instalator pobierał jeden plik `.deb` i podawał go każdemu systemowi opartemu na Debianie. Ten plik jest budowany na Debianie 13 i, jak każdy program tego rodzaju, stanie tylko obok dokładnie tej wersji Qt, z którą go zbudowano - więc na Ubuntu był odrzucany ścianą tekstu o `qt6-base-private-abi`, a instalator poddawał się i proponował wersję przenośną. Teraz najpierw dodaje własne źródło oprogramowania Unisica i instaluje z niego, bo to tam leży wydanie zrobione pod Twój system: Debian 13 oraz Ubuntu 25.10/26.04 z tego źródła, Fedora z COPR-a Unisica, openSUSE jak dotąd. Aktualizacje przychodzą potem razem ze zwykłymi aktualizacjami systemu i nie trzeba nic więcej ustawiać. Na systemie, dla którego nie mamy jeszcze wydania, instalator mówi to wprost, mimo wszystko próbuje paczki z Debiana 13, a gdy zostanie odrzucona, wkłada wersję przenośną do Twojego katalogu domowego, zamiast zostawić Cię z niczym. Wybór konkretnej starszej wersji nadal pobiera ją ze strony wydań, bo źródło oprogramowania ma zawsze tylko najnowszą.
- **Zapisane hasła serwerów mogły odczytać inne konta na tym samym komputerze**: plik z Twoimi celami wysyłki - loginami FTP i SFTP oraz kluczami API wpisanymi we własnym serwerze - był zapisywany z uprawnieniami, jakie dostaje każdy zwykły nowy plik, więc dowolne inne konto użytkownika na tej maszynie mogło go otworzyć i przeczytać. Teraz odczytasz go tylko Ty, a plik pozostawiony przez wcześniejszą wersję zostaje uszczelniony przy pierwszym otwarciu przez tę. Niczego nie trzeba wpisywać od nowa. Na komputerze, z którego korzystasz tylko Ty, nic nigdy nie było w zasięgu kogokolwiek innego.
- **Program uruchamiany po każdym przechwyceniu nie może już wisieć w nieskończoność**: Ustawienia › Przechwytywanie › Zewnętrzna akcja przekazuje każde nowe przechwycenie wybranemu przez Ciebie programowi. Jeśli ten program nigdy się nie kończył - utknął na dysku sieciowym albo czekał na odpowiedź w terminalu, którego nie widzisz - Unisic czekał razem z nim do końca sesji, a tymczasowa kopia przechwycenia zostawała na dysku. Taki program dostaje teraz dwie minuty, po czym zostaje zatrzymany, a Ty dostajesz o tym komunikat, a gdy dwie minuty to zła miara dla tego, co Twoje polecenie naprawdę robi, limit ustawisz sam w Ustawieniach › Przechwytywanie › Zewnętrzna akcja › „Poddaj się po" - od 10 sekund do godziny. Naraz działają najwyżej cztery, więc przytrzymanie klawisza przechwytywania nie nazbiera już ich bez ograniczeń. Same komunikaty też zostały napisane od nowa: zamiast „program not found: oxipng" dostajesz nazwę brakującego programu i to, co z tym zrobić.
- **Nazwa zapisu zaczynająca się od kropki nie ukrywa już przechwycenia**: szablon nazwy w Ustawieniach › Zapisywanie przyjmuje wszystko, co wpiszesz, a nazwa zaczynająca się od kropki dawała plik ukryty - zapisany bez słowa sprzeciwu, a potem niewidoczny w każdym menedżerze plików, w którym byś go szukał. Wiodąca kropka jest teraz usuwana, tak samo jak kropki i spacje na końcu, przez które pliku nie da się skopiować na udział Windows albo FAT.
- **Dodatkowe motywy kolorów wracają, gdy zniknęły**: Dracula, Nord, Gruvbox i dwa warianty Catppuccin są raz kopiowane do Twojego folderu motywów, żebyś mógł je zmieniać albo usuwać jak każdy własny motyw. Unisic zapisywał sobie w ustawieniach, że już to zrobił, i nigdzie indziej - więc plik ustawień przeniesiony na inny komputer, odtworzony z kopii zapasowej albo podchwycony przez wersję beta przychodził z informacją „już zrobione", a folderu motywów obok niego nie było i tych pięciu palet nie było tam już nigdy. Teraz sprawdzany jest sam folder: gdy go brakuje, motywy są zapisywane ponownie, a usunięcie pojedynczych motywów w środku nadal je usuwa na stałe. Paleta dodana w późniejszej wersji trafia też do istniejącej instalacji, czego wcześniej nie robiła.
- **Instalator uruchamiany z aplikacji jest teraz sprawdzany przed uruchomieniem**: „Zainstaluj teraz" w Ustawieniach › Aktualizacje pobiera mały skrypt i uruchamia go z Twoim hasłem, żeby zainstalować nową wersję. Do tej pory sprawdzane było tylko to, czy plik wygląda na instalator Unisica. Każde wydanie publikuje teraz ten skrypt jako swoją część, razem z jego odciskiem, a Unisic porównuje jedno z drugim, zanim cokolwiek się uruchomi. ## 0.7.4

### English
**New**
- **Global hotkeys on desktops that don't offer them (COSMIC, Xfce and more)**: on a desktop with neither KDE's global shortcuts nor a working GlobalShortcuts portal, Unisic could not register capture hotkeys at all. It now binds each capture action to a command in the desktop's own keyboard settings. On COSMIC, GNOME/Budgie, Cinnamon and Xfce it writes those shortcuts for you with one click (Settings › Hotkeys › “Add shortcuts to …”), using the keys you record right there - and they stay fully editable in the desktop's own settings afterwards. Everywhere else (niri, Hyprland, sway, …) the same screen lists the exact commands to paste. A new `unisic --hotkey <action>` command line backs all of it, and Unisic only ever writes its own entries - your other custom shortcuts are left untouched.
- **Capture hotkeys on the Singularity desktop**: Singularity offers no global-shortcut system apps can use (no GlobalShortcuts portal, no custom-command shortcuts of its own), so Unisic's hotkeys were simply dead there. “Add shortcuts to Singularity” now writes Unisic's keybinds straight into the desktop's compositor configuration and reloads it on the spot. Singularity regenerates that file on every login and whenever its own shortcuts change - so Unisic also watches it and puts its entries back the moment they disappear; removing them in Settings still sticks.
- **A setup flow on the first launch**: Unisic now opens with a short walkthrough inside its own window - theme (every installed one, including the Catppuccin/Dracula/Nord/Gruvbox files), language and window decoration; what happens after each capture (save, clipboard, editor); a few behaviours worth deciding on (ask-where-to-save, stay in the tray, start at login); the capture card, with a live preview right in the window where you pick its style and corner and click the action buttons to add or remove them; and the capture shortcuts, which can be recorded on the spot. The card's action buttons are live in that preview: hover one to see what it does, click to remove or restore it, and hold and drag to reorder them, with the row animating each swap. Every step is optional: skip it and the shipped defaults stay. It only ever appears on a fresh install - updating an existing Unisic never interrupts you with it - and you can reopen it any time from Settings › General › Diagnostics.

**Fixed**
- **The KDE title bar no longer lingers after switching to the styled decoration**: turning the system window decoration off left KWin's title bar painted on top of Unisic's own until you clicked outside the window. The window now re-maps itself so the change takes effect immediately.
- **Click selects the whole screen**: on the region-selection overlay, a plain click (no drag) now selects the entire screen you clicked on - annotate and confirm as usual. With “Capture on release” enabled the click captures immediately. Dragging still selects a region, exactly as before.
- **Keep region between captures** (Settings › Capture): the selection overlay opens with your last region already pre-selected on its screen - repeating a shot is just Enter, or a drag to adjust. The rectangle survives an app restart.
- **Full screen captures** (Settings › Capture): choose what the full-screen capture takes - all monitors stitched together (the default, as before) or only the screen under the cursor. Applies to the hotkey, the tray entry and `unisic --fullscreen` alike.
- **Screenshots and recordings no longer crash the app on COSMIC**: on System76's COSMIC desktop the capture card, the region-selection overlay and the record-region frame each disconnected Unisic from the display the instant they closed - a quirk in how this compositor tears down these on-top surfaces - so every screenshot and every recording took the whole app down with it. Unisic now draws those surfaces the same way it does on GNOME, and both capture and recording run through cleanly.

**Changed**
- **Fewer hotkeys**: “Capture screen under cursor” and “Re-capture last region” are no longer assignable hotkeys - the two new capture preferences cover both jobs with the keys you already have. The features themselves remain in the tray menu and on the command line (`unisic --monitor`, `unisic --recapture`); any key you had bound to them is released cleanly on upgrade.
- **Scroll to zoom the pixel loupe, no modifier**: on the region overlay the magnifier now zooms with a plain scroll (Ctrl is no longer needed) in single, pixel-perfect steps. Scroll all the way out and the loupe hides itself so it stops covering what you are aiming at; scroll back in to bring it straight back.

**Improved**
- **WebM recordings convert several times faster on recent NVIDIA GPUs**: WebM can't carry H.264, so hardware encoding never applied to it and every WebM conversion ran on the CPU - a long recording could take longer to convert than to record. **Fixed**
- **A recording can no longer hang forever on "Encoding…"**: if the audio source died mid-recording (a PipeWire link failure), the encoder inside ffmpeg could deadlock waiting for sound that would never arrive - the recording never finished, and memory grew without bound until the app was killed, taking the recording with it. Wskaźnik jest rysowany tylko wtedy, gdy pulpit faktycznie go pokazuje, więc gra chowająca kursor zostaje bez kursora. - **Presety stylu**: gdy kolor, grubość i font są już dobrane, **+** na końcu opcji narzędzia zapamiętuje cały ten styl jako kropkę. Kliknięcie kropki przywraca styl - w edytorze i na nakładce przechwytywania (do sześciu; środkowy przycisk usuwa).

**Ulepszone**
- **Wideo zapisuje się dużo szybciej**: nagrania używają teraz domyślnie działającego enkodera sprzętowego (VAAPI/NVENC), gdy maszyna faktycznie go ma, zamiast zawsze kodować na procesorze. Enkoder sprzętowy wymieniony, lecz zepsuty, jest wykrywany i pomijany. WebM zostaje wyłącznie programowy i jest teraz nastrojony na kilka razy szybszy zapis.

- **Podgląd karty na żywo**: rozwiń listę stylu, pozycji lub odległości karty przechwytywania, a prawdziwa karta pojawi się na ekranie - przechodzenie po opcjach przeprowadza kartę przez kolejne warianty, więc każdy widzisz dokładnie tam, gdzie stanie karta następnego zrzutu, zanim go wybierzesz.
- **Wybierz przyciski karty przechwytywania** (Ustawienia › Powiadomienia): wyłącz akcje, których nie używasz, a reszta rozłoży się na zwolnionym miejscu.
- **Przytnij wprost z powiadomienia**: karta gotowego nagrania ma teraz przycisk Przytnij, obok tych, które dostaje zrzut - bez wycieczki przez Historię.
- **Edytuj** to teraz osobna zakładka: otwórz zdjęcie, które już masz, w edytorze, albo film w oknie przycinania. Unisic edytuje Twoje własne pliki, nie tylko własne zrzuty.
- Wiersz poleceń: `--delay SEKUNDY`, `--output <ścieżka>` (`-` dla stdout), `--format png|jpg|webp` oraz `--measure`.

**Naprawiono**
- Na GNOME zmiana kolejności przypiętych ikon w Ubuntu Dock podczas nagrywania obszaru już działa. Ramka nagrywania jest rysowana jako cztery cienkie krawędzie wokół obszaru zamiast jednej pełnoekranowej powierzchni, więc nic nie zasłania reszty pulpitu (a przeciąganie wewnątrz nagrywanego obszaru też działa). Dzięki zgłoszeniu użytkownika, które to namierzyło.
- **Podfoldery z datą** grupują teraz także nagrania, nie tylko zrzuty.
- Na GNOME karta przechwytywania nie ląduje już pod górnym paskiem ani pod dokiem: jest teraz umieszczana w obszarze roboczym pulpitu, a nie w surowym prostokącie ekranu. (Tam, gdzie jest layer-shell - KDE, wlroots, COSMIC - panele i tak odsuwały kartę.)
- Dźwięk zrzutu jest teraz dźwiękiem powiadomienia, więc nie zakłóca innego audio (np. przechwytywania udostępniania ekranu na Discordzie).
- Znaczniki pomocy **„?”** w Ustawieniach nie nachodzą już na szerokie pola, a zduplikowany kursor ze znakiem zapytania zniknął.
- Na pulpitach bez backendu portalu ScreenCast (Cinnamon, MATE, XFCE) strony nagrywania twierdziły, że Unisic „zbudowano bez obsługi PipeWire” - nieprawda, i mylące, gdy proces PipeWire jawnie działa. Teraz nazywają to, czego naprawdę brakuje: portalu, który pyta o zgodę i otwiera strumień.

**Usunięto**
- **Inteligentny wybór** (eksperymentalna opcja klikania w obiekt w Ustawieniach › Przechwytywanie) zniknął. Wykrywanie było czysto wizualne i nigdy nie rozpoznawało okien ani elementów na tyle pewnie, by je zostawić. Zaznaczanie obszaru przeciąganiem działa bez zmian.
- Akcja **Usuń tło** w edytorze i ustawienia modelu U-2-Net zniknęły wraz z opcjonalną zależnością onnxruntime. Inteligentna gumka działa bez zmian.
- Wbudowany serwer **0x0.st** zniknął - odrzucał wysyłki, więc dawał wyłącznie błędy. Jeśli był Twoim wybranym serwerem, Unisic przełącza z powrotem na catbox.moe; Twoje własne serwery zostają nietknięte.
